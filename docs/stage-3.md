# Stage 3: read-only HA preview (development)

No live deployment. Do not install on production until HA compatibility and access review. Install custom_components/rotacloud_attendance only on a test HA instance, restart and add RotaCloud Attendance under Settings > Devices & services. Enter the API key directly in HA, never GitHub or chat; terminal ID is reserved for a later secure gateway. Config-entry storage is not encrypted by this component; protect HA backups and admin access.

Default: five-minute live/completed polling; shift cache 15 minutes; employee directory 60 minutes. At steady state without events or pagination approximately 29 requests/hour (12 live + 12 completed + 4 shift + 1 staff). Account-specific quota unknown; 429 honors Retry-After and exponential fallback. Options: 120–3600 seconds poll; late grace 0–60 minutes; leaving threshold 0–120 minutes. Live statuses: here, break, leaving (within configured finish threshold of explicitly linked shift, including overdue), due (future shift), late (unfulfilled shift past start/grace), gone (completed and no pending shift). Past missed shifts remain late. Unscheduled clock-ins included. Native sensors: counts and individual status with timestamp attributes (Unix seconds). Dashboard should derive live timers locally from timestamps. Gross elapsed duration excludes no breaks. Completed break seconds across today's overlapping records are a separate field; not paid hours.

Existing webhook receiver can emit HA event rotacloud_attendance_refresh, optionally with refresh_rota: true. Only after explicit migration review; current receiver unchanged. Event triggers a fresh GET, not a trusted mutation. Refreshes within 30 seconds of previous attempt are suppressed; polling reconciles. No new external endpoint or webhook registration in this version. Direct signed webhook receiver remains future work.

Privacy: any HA account with access to entities may see staff names/status; kiosk must not have HA credentials or direct access to HA entity API. Staff sensor timing attributes are marked unrecorded; explicitly exclude individual staff sensors from Recorder if state history not needed, and verify actual HA recorder behaviour. Do not expose these sensors to voice assistants or public dashboards. Entity registry may retain names. This is not a staff-facing interface.

Known limitations: shift selection uses explicit attendance shift ID for actual comparisons; unlinked attendance does not infer an association. Multiple or missed shifts can need management review; real-world association, clock corrections, crossing midnight, missing break details and response pagination require pilot verification. No clock actions, PIN UI, external webhook authentication, reauthentication flow or dashboard installed. No HA runtime tests performed yet. Existing official terminal remains available. See README for future checkpoints.
