# Stage 4: low-traffic coordinator + terminal backend prototype

Version 0.3.0-dev.1. No production release. Existing installations require an explicit update; no settings are changed remotely.

## API budget
Default hourly live fallback, configurable 30 minutes to 24 hours, or 0 (event-only). Existing settings preserved, but old intervals under 30 minutes are clamped at runtime. Rota cache six hours, directory 24 hours, completed history six hours plus clock-out/disappearance, generic attendance webhook and day rollover. At 30-minute fallback, quiet steady-state budget approximately 48 live + 4 shifts + 4 history + 1 directory = 57 requests per day, excluding pagination, startup, clocking, external events and changes. At one hour approximately 33/day. Event-only mode fetches on startup, day change and relayed events; external breaks without webhooks can be missed indefinitely until next read. Status transitions computed locally once per minute. Webhook relaying still requires setup; existing receiver unchanged. 429 cooldown is shared on the client, begins at 15 minutes, respects longer Retry-After, and escalates on further 429. Other apps sharing the same key may still exhaust the quota. No published numeric quota. Never deliberately hit the quota.

## Terminal backend
The new terminal.py is a gateway-independent service prototype with short one-use device-bound sessions, server-authorised employee eligibility, PIN attempt throttling, serialised writes, rechecking fresh attendance before action, shift allowlist, no automatic retry and confirmed-response state update callback. Each successful interaction normally costs PIN lookup + live lookup + pre-write live recheck + one mutation (4 calls, excluding pagination and reconciliation). The extra pre-write read protects payroll from stale actions. No PIN stored in session or HA state. RotaCloud PINs are URL path components upstream; audit proxy/trace/debug logging. No employee ID accepted from the browser as a mutation argument. Current prototype uses in-memory sessions and a global eight-attempt/minute ceiling; pilot tune throughput and add failed-attempt/device controls. Shift eligibility callback and account policies must be implemented before exposing this service. Clock-out break totals are provisional pending saved record reconciliation; no extra read for each break start/end. The live coordinator callback, kiosk HTTP transport, authentication provisioning, TLS/local-only network policy, actual kiosk UI and dedicated RotaCloud terminal registration are still outstanding. No public routes, no HA write services, no live API tests. Unit tests added, execution pending.
